# Промпт № 3. Локальный запуск бота

Запусти Telegram-бота лабораторной № 1 на этом Mac из корня `itmo-tg-template`. Доведи запуск до работающего polling и успешного healthcheck. Используй текущую рабочую копию, включая незакоммиченный код. Прочитай `AGENTS.md`, разделы 1–5 и 9 `README.md`, проверь `git status`. Выполняй shell-команды через `rtk`.

## Подготовь окружение

1. Проверь Python 3.12, доступность Docker и Compose v2. Подойдёт существующая `.venv` с Python 3.12. Если Docker Desktop установлен, но ещё не запущен, открой его и дождись готовности. Используй локальный Docker, чтобы поднять PostgreSQL этого проекта.
2. Проверь наличие `.env` и его исключение из Git. Для проверки настроек используй штатный загрузчик `Settings.load()` и сообщай только имена отсутствующих или некорректных параметров. Обязательны `BOT_TOKEN` и `OPENROUTER_API_KEY`. Пароль БД создаёт скрипт при первой настройке. Для моделей и адреса OpenRouter используй существующий бесплатный пул и штатные значения. Не выводи `.env`, переменные окружения, значения ключей, токенов, паролей или адреса прокси с учётными данными.
3. Если окружение ещё нужно подготовить или нужно создать `.env`, выполни `rtk proxy bash scripts/start.sh --setup-only`. При первом запуске скрипт может запросить токен Telegram и адрес прокси через скрытый ввод. Если требуется ввод пользователя, попроси его выполнить эту команду в своём терминале. Ключ OpenRouter пользователь указывает в локальном `.env` через редактор, в поле `OPENROUTER_API_KEY`. Если чего-то не хватает, сообщи конкретный шаг и продолжи после настройки. Секреты вводятся только локально.

## Запусти и проверь

1. Проверь, не работает ли уже бот этого проекта. Если он запущен и проходит проверку, используй этот экземпляр. Иначе запусти `rtk proxy bash scripts/start.sh` в долгоживущей терминальной сессии. Команда поднимет БД и запустит бота на переднем плане. Оставь бота работать после проверки. Если сессия агента закроется вместе с процессом, используй уже доступную отдельную терминальную сессию или дай пользователю команду для его терминала.
2. В отдельной сессии выполни `rtk proxy bash scripts/start.sh health`. При отказе проверь `rtk proxy bash scripts/start.sh status` и диагностические сообщения бота. Команда `status` проверяет контейнер БД. Healthcheck проверяет работу polling и ответ PostgreSQL на `SELECT 1`.
3. Для сквозной проверки попроси пользователя отправить боту в личном чате `/start`, затем «Объясни разницу между списком и кортежем в Python в двух предложениях». Подтверди ответ модели только после фактической проверки. Сообщи отдельно результат healthcheck и результат проверки OpenRouter в Telegram.
4. Если Telegram возвращает `Conflict`, проверь второй экземпляр бота. При обнаружении webhook, занятого порта или чужого процесса сообщи точную причину и какое действие требуется от пользователя. Сохрани контейнеры и данные PostgreSQL. Для остановки бота в терминале используй `Ctrl+C`. Команда `rtk proxy bash scripts/start.sh stop` останавливает PostgreSQL отдельно.

Работай только с локальным запуском. Используй штатные команды и локальные настройки. В конце сообщи, где работает бот, как проверить и остановить его, и что ещё нужно сделать, если запуск не удалось завершить.
