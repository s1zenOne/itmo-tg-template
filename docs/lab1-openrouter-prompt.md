# Промпт № 2. Перевод бота на OpenRouter

Работай из корня `itmo-tg-template`. Переведи LLM-клиент лабораторной № 1 на OpenRouter API и заполни конфигурацию актуальным пулом бесплатных моделей. Сначала прочитай `AGENTS.md`, `README.md` и [требования лабораторной](labs-guide.md#lab1). Проверь `git status` и посмотри текущие `app/llm.py`, `app/config.py`, `app/service.py` и `scripts/lab1_experiment.py`. Незакоммиченные изменения первой лабораторной могут быть частью текущей работы. Сохрани их и отделяй свои изменения при коммите.

## Сначала собери пул и заполни конфиг

1. Получи свежий каталог из `GET https://openrouter.ai/api/v1/models`. Оставь точные ID с суффиксом `:free`, текстовым входом и выходом, нулевыми `pricing.prompt` и `pricing.completion` и поддержкой `temperature`. Для кандидатов запроси `GET /api/v1/models/{author}/{slug}/endpoints`, сохранив суффикс `:free`. Проверь, что есть доступный бесплатный эндпоинт с `temperature` и без платы за текстовый запрос. Сравни цены как числа. Исключи агрегаторы `openrouter/free` и `openrouter/auto`, платные варианты и эндпоинты для эмбеддингов или классификации. [Каталог моделей](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties), [эндпоинты модели](https://openrouter.ai/docs/api/api-reference/endpoints/list-all-endpoints-for-a-model).
2. Выбери до четырёх моделей в порядке приоритета. Предпочти модели от разных провайдеров с достаточным контекстом для `/study`, `/translate` и `/quiz`. Впиши **точные ID в рабочие значения конфигурации по умолчанию и в `.env.example`**. Используй `OPENROUTER_MODELS` как список через запятую, первая модель — основная. При чтении конфигурации сохраняй порядок, проверяй непустой список и отклоняй дубликаты и любые значения вне формата конкретного бесплатного ID. Укажи в README дату проверки и как обновить список. Если каталог недоступен, отметь, какие модели остались непроверенными, и не добавляй платный резерв.

Кандидаты, проверенные 10 ноября 2026 года по каталогу и эндпоинтам. У каждого из них были нулевые цены входа и выхода и заявленная поддержка `temperature`. Перед записью повтори проверку. Эти данные не подтверждают успешную генерацию с ключом пользователя.

## Подключи OpenRouter и переключение между моделями

- Используй существующий асинхронный HTTP-клиент и `POST https://openrouter.ai/api/v1/chat/completions`. Задай `OPENROUTER_API_BASE_URL` по умолчанию как `https://openrouter.ai/api/v1` и читай ключ из `OPENROUTER_API_KEY`. Передавай ключ через `Authorization: Bearer`. В `.env.example` оставь ключ пустым. Обнови проверку настроек, фильтр секретов, локальный запуск и проброс параметров в Compose. В README объясни переход со старых `LLM_API_KEY`, `LLM_API_BASE_URL` и `LLM_MODEL`. Старый адрес и ключ не должны использоваться автоматически. Реальный ключ передавай только официальному хосту OpenRouter по HTTPS. [Chat Completions API](https://openrouter.ai/docs/api/api-reference/chat/create-a-chat-completion).
- Передавай `messages` с ролями и числовой `temperature`, включая `0.0`. Для каждого запроса используй `provider.require_parameters: true` и нулевой `provider.max_price` для `prompt`, `completion` и `request`. Указывай один точный `model` за попытку. При временном сбое или лимите конкретного эндпоинта пробуй следующую модель только из пула. Ограничь все попытки одним общим таймаутом, учитывай `Retry-After` и останавливайся при общей квоте аккаунта, ошибках авторизации, валидации или модерации. Встроенный список `models` у OpenRouter запускает резерв и при ошибках модерации, поэтому переключение контролирует адаптер. Если бесплатные модели недоступны, верни понятное сообщение на русском. [Настройки маршрутизации](https://openrouter.ai/docs/guides/routing/provider-selection), [условия переключения](https://openrouter.ai/docs/guides/routing/model-fallbacks), [лимиты бесплатных моделей](https://openrouter.ai/collections/free-models/).
- Сохрани режимы, историю в PostgreSQL, `/reset`, настройки и разбиение длинных сообщений. В `/settings` показывай основную модель и наличие бесплатного резерва. В метаданных каждого ответа фиксируй фактическую модель из ответа OpenRouter, провайдера и расход токенов, если доступны. Привязывай эти данные к конкретному запросу, чтобы параллельные ответы не перезаписывали их друг у друга. Не логируй ключ, текст запросов, ответы и сырые тела ошибок.

## Проверь работу и обнови отчёт

- Добавь тесты с подменой HTTP для разбора конфига, передачи ролей и четырёх температур, перехода на резерв при временном сбое, исчерпания пула и отсутствия перехода при ошибках ключа, валидации и модерации. Проверь фактическую модель в метаданных ответа и отсутствие платных ID в запросах. Запусти `pytest`, `ruff check`, `ruff format --check` и `pip check` по инструкции проекта.
- В `scripts/lab1_experiment.py` закрепи одну бесплатную модель и один её эндпоинт на все 12 запусков. Передавай один `model`, закрепи эндпоинт настройками `provider` и выключи `allow_fallbacks`. При наличии настроенного ключа проверь на синтетическом диалоге роли и приём всех четырёх температур. Для серии делай сброс перед каждым запросом и записывай фактическую модель и провайдера. Если маршрут изменился, не смешивай результаты разных моделей или провайдеров в одной серии. При недоступности ключа, модели или лимите укажи в отчёте, какие шаги предстоит выполнить. В таблицу эксперимента включай только реальные ответы.
- Обнови `README.md` и `docs/lab1-report.md` по фактически полученным результатам. Фиксируй каждую завершённую логическую правку отдельным Git-коммитом после проверки. Проверь staged diff, включи только свои изменения и сообщи выбранный пул, результаты проверок и хеши коммитов.
