# Агенты и запуск лабораторной № 3

Запустите из корня проекта, войдя заранее в Codex CLI:

```bash
rtk proxy codex --search exec --enable multi_agent -C "$PWD" - < docs/lab3-prompt.md
```

Команда запускает длительную работу с изменением файлов проекта и локальными
коммитами согласно `AGENTS.md`. Она использует доступные Codex инструменты,
текущие модель и настройки разрешений; специального режима обхода ограничений
не включает. Нужны установленный `rtk`, авторизованный Codex CLI и доступные
субагенты. Для отдельных проверок понадобятся зависимости проекта, PostgreSQL,
Docker и доступ к модели. Если проверка недоступна, исполнитель должен указать
причину и команду для её повторения. Не запускайте второй polling-процесс с тем
же токеном Telegram.

`lab3-prompt.md` — задача координатору. Он создаёт субагентов, распределяет
работу и ждёт их заключений. Роли ниже — задания для субагентов, а не отдельные
программы или гарантированные процессы: доступность и число параллельных агентов
зависят от среды. При нехватке слотов роли выполняются очередями. Если субагенты
недоступны, координатор явно сообщает об этом и выполняет доступную проверку сам,
не называя её независимым ревью.

## Роли

1. **Аналитик требований**: до реализации сопоставляет раздел лабораторной № 3,
   общие правила и обязательные функции работ № 1–2 с текущим кодом. Возвращает
   матрицу «требование → место в коде → проверка → пробел», особенно по границам
   полномочий, контрактам и сдаче. Исходники не меняет.
2. **Ревьюер требований и регрессий**: после реализации независимо сверяет код,
   тесты и документацию с методичкой и матрицей. Проверяет прежние режимы,
   команды, миграции и переносимость. Возвращает проверяемые замечания с путями,
   строками и описанием сценария; при отсутствии замечаний указывает проверенный
   объём и оставшиеся риски. Исходники не меняет.
3. **Ревьюер безопасности**: после реализации проверяет реальное применение
   политик инструментов и ресурсов, доверенные идентификаторы и адрес доставки,
   подтверждения, инъекции, изоляцию пользователей и приватность трасс. Проверяет,
   что тесты наблюдают фактические вызовы и побочные эффекты. Возвращает замечания
   с доказательствами. Исходники не меняет.
4. **Ревьюер фоновой доставки**: после реализации проверяет транзакции и гонки
   PostgreSQL, границы времени и часовых поясов, восстановление, повторы,
   частичные отказы и согласие перед отправкой. Отдельно проверяет, что тесты
   используют управляемое время и реальный PostgreSQL там, где этого требует
   методичка. Возвращает замечания с доказательствами. Исходники не меняет.

Координатор устраняет подтверждённые замечания, повторяет затронутые проверки и
организует повторное ревью исправлений. Все роли сверяются с актуальным текстом
методички, а не только с кратким перечнем в этом файле.
