# Как работает лабораторная № 1

В этой работе мы сделали Telegram-бота для студента. Он объясняет программирование, переводит текст и задаёт вопросы для тренировки. Бот получает сообщения через Telegram, просит языковую модель сформировать ответ через OpenRouter и хранит историю и настройки каждого чата в PostgreSQL. Благодаря этому можно продолжить диалог после перезапуска бота.

## Основные термины

| Термин | Что он значит в этой работе |
| --- | --- |
| **LLM** (большая языковая модель) | Генерирует текст ответа по переданной инструкции, истории и новому сообщению. |
| **API** | Интерфейс, через который программы обмениваются данными. Telegram Bot API доставляет сообщения, а OpenRouter Chat Completions API принимает запросы к модели. |
| **OpenRouter, модель и эндпоинт** | OpenRouter принимает запрос и направляет его провайдеру. Модель генерирует текст. Эндпоинт обозначает конкретный маршрут к модели у провайдера. |
| **Long polling** | Бот сам отправляет запрос за обновлениями в Telegram и ждёт новые сообщения. Получив ответ, он снова запрашивает обновления. |
| **Системный промпт** | Инструкция приложения о том, какую задачу выполняет модель и как оформляет ответ. В запросе у неё роль `system`. |
| **Few-shot** | Несколько примеров входа и ожидаемого ответа прямо в инструкции. В режиме `/quiz` примеры показывают, как задать вопрос по теме и что ответить, когда темы нет. |
| **Контекст** | Вход, который получает модель для конкретного ответа. Здесь это системная инструкция, недавние пары реплик и текущий запрос. |
| **Токен модели** | Единица, на которую модель делит текст. Токен может быть частью слова или знаком. В коде объём входа оценивается по символам, а статистику токенов приложение берёт из ответа API, если она доступна. |
| **Температура** (`temperature`) | Параметр генерации. Низкие значения обычно дают более похожие ответы, высокие — более разнообразные. Точность и повторяемость нужно проверять по результатам. |
| **Пул подключений** | Набор переиспользуемых подключений к PostgreSQL. Бот берёт подключение из пула на время операции с базой. |

## Команды бота

| Команда | Что происходит |
| --- | --- |
| `/start` | Показывает список команд. |
| `/study` | Включает учебного помощника. В этом режиме бот начинает работу с новым чатом. Промпт просит дать короткий ответ, объяснить его по шагам и разобрать типичную ошибку. |
| `/translate` | Включает перевод. Язык и текст передаются следующим сообщением, например «Переведи на английский фразу „Доброе утро“». |
| `/quiz` | Включает тренировку. После команды отправьте тему. По инструкции модель задаёт один вопрос, а после ответа студента оценивает его и задаёт следующий. |
| `/settings` | Показывает режим, основную модель из настроек, наличие резерва и температуру. Команда `/settings 0.7` сохраняет новое значение для следующих запросов. Допустимы `0.0`, `0.3`, `0.7` и `1.0`. |
| `/reset` | Удаляет историю этого чата. Режим и температура сохраняются. |

Команды обрабатывает код бота. Команды выбора режима очищают историю чата, даже если пользователь повторно выбирает активный режим. Для нового чата начальная температура равна `0.3`. [Обработчик Telegram](../app/handlers/assistant.py) · [Системные инструкции](../app/prompts.py)

## Что происходит с одним сообщением

Представим, что студент включил `/quiz`, отправил «Списки Python» и получил вопрос о разнице между `append` и `extend`. Теперь он отвечает «`append` добавляет один элемент, `extend` добавляет элементы из другой последовательности».

1. **Telegram доставляет ответ студента.** Обработчик на aiogram принимает текст в личном чате и включает индикатор «печатает». Сообщения из групп и вложения без текстового сообщения этот обработчик пропускает.
2. **Сервис загружает состояние чата.** По `chat_id` он читает из PostgreSQL режим `quiz`, температуру и недавние реплики.
3. **Код собирает запрос к модели.** Первой идёт инструкция `system` для тренировки, затем тема студента (`user`) и предыдущий вопрос бота (`assistant`), последним идёт новый ответ студента (`user`). Так модель получает вопрос, по которому нужно оценить ответ.
4. **Клиент отправляет запрос в OpenRouter.** В JSON передаются ID модели, массив `messages` с ролями и числовая `temperature`. Из ответа клиент извлекает текст и проверяет, что он пригоден для отправки.
5. **Бот сохраняет обмен и отправляет ответ.** Сервис записывает реплику студента и текст модели в PostgreSQL. Обработчик Telegram делит длинный текст на части до 4096 символов и отправляет их по порядку без разбора разметки.

~~~text
Telegram → обработчик aiogram → сервис
                                ↕
                           PostgreSQL

           сервис → сборка контекста → OpenRouter → модель
Telegram ← обработчик ← сервис ← клиент OpenRouter ← ответ
~~~

При запуске приложение на Python 3.12 проверяет подключение к PostgreSQL и доступ к Telegram, создаёт таблицы при необходимости и запускает polling. При локальном запуске Python работает на компьютере, а PostgreSQL — в Docker. Telegram-обновления обрабатываются последовательно, поэтому долгий ответ модели может задержать обработку следующего сообщения. [Точка входа](../app/__main__.py) · [Сервис диалога](../app/service.py) · [Клиент OpenRouter](../app/llm.py)

## Как устроены история и контекст

В PostgreSQL две таблицы. `chat_settings` хранит режим, температуру и номер версии истории (`generation`) по идентификатору чата. `chat_history` хранит реплики с идентификатором чата, порядковым номером, ролью и текстом. Запросы к базе передают значения отдельными SQL-параметрами. Когда приложение перезапускается, оно снова читает состояние из тех же таблиц. [Хранилище](../app/store.py)

В запрос к модели по умолчанию попадает до **12 реплик истории**, то есть до шести полных пар «пользователь → ассистент». Это число не включает системную инструкцию и текущий запрос. Для всей входной последовательности действует бюджет в **12 000 оценочных символов**. Код считает длину текста, длину названия роли и запас в 16 символов на каждое сообщение. Пары отбираются от новых к старым и передаются в хронологическом порядке. Если очередная пара не помещается, отбор останавливается. Бот отклоняет запрос до вызова API, если даже инструкция вместе с новым сообщением превышает бюджет. Старые реплики при таком ограничении остаются в базе. [Сборка контекста](../app/context.py) · [Настройки лимитов](../app/config.py)

При `/reset` или выборе режима хранилище в одной транзакции увеличивает `generation` и удаляет реплики этого чата. Перед сохранением хранилище сверяет текущую версию истории с версией, которую сервис прочитал перед вызовом модели. Если другой процесс успел очистить историю, хранилище отклоняет запоздалую запись. Внутри процесса сервис дополнительно использует отдельную блокировку на чат. [Транзакции хранилища](../app/store.py) · [Блокировки и обработка результата](../app/service.py)

## Как бот переживает сбои

- При временном сбое, например ограничении частоты у провайдера, клиент может перейти к следующей модели из настроенного списка `:free`. В запросе указаны нулевые пределы цены. Ошибка авторизации, исчерпанная квота аккаунта и отказ по правилам контента останавливают попытки.
- У всех попыток один общий таймаут. По умолчанию он равен 30 секундам. Если модель вернула ошибку, пустой или некорректный ответ, бот показывает короткое сообщение. В истории может остаться реплика пользователя, но реплика ассистента при ошибке не создаётся. При сборке следующего контекста одиночную реплику пропускают.
- Логи попыток содержат случайный ID запроса, модель, длительность и результат. Ключ OpenRouter, инструкция и переписка в эти логи не записываются.
- `/health` — HTTP-адрес диагностики приложения. Статус `200` означает, что бот инициализирован, задача polling работает и PostgreSQL отвечает на `SELECT 1`. Для проверки модели отправляют отдельное сообщение боту.

## Эксперимент с температурой и промптами

В основной серии меняется только температура. Скрипт задаёт один и тот же вопрос про подсчёт частоты слов в Python, сохраняет один системный промпт и закрепляет одну модель и один эндпоинт. Перед каждым прогоном он сбрасывает историю синтетического чата. По три прогона для каждого из четырёх значений дают **12 ответов**. Для каждого ответа сохраняются текст, длина, модель, провайдер и счётчики токенов, если API их вернул. Формат, полноту, понятность и фактическую корректность нужно оценить вручную.

Отдельно при `0.3` сравниваются два промпта на вопросе про изменяемый аргумент функции Python по умолчанию. Короткий промпт только просит ответить, а полный задаёт роль, аудиторию, структуру и пример. Это применение **R.C.T.F.** (роль, контекст, задача, формат). В ответах сравнивают ясность объяснения, наличие исправления, работоспособность примера и фактические ошибки.

Из корня проекта на macOS или Linux, с настроенным ключом OpenRouter и запущенной PostgreSQL, эксперимент запускается так.

~~~bash
.venv/bin/python -m scripts.lab1_experiment
~~~

Перед серией скрипт делает четыре предпроверочных запроса с синтетическим диалогом. Затем идут 12 измерений и два вызова для сравнения промптов. Результат пишется в `.lab1/`. Скрипт обращается к API напрямую и останавливается, если фактическая модель или провайдер меняются либо провайдера невозможно определить. [Код эксперимента](../scripts/lab1_experiment.py) · [Требования методички](labs-guide.md#lab1)

## Что проверено и как показать работу

В отчёте от 10 ноября 2026 года зафиксированы 96 пройденных тестов, отдельная Docker-проверка PostgreSQL и успешный локальный `/health`. Telegram принял реальный ответ резервной модели после HTTP 429 от основной. По тому же отчёту таблица из 12 ответов, сравнение промптов и полная демонстрация с двумя аккаунтами ещё не выполнены. Значение `0.3` выбрано как начальная настройка. [Результаты и сценарий демонстрации](lab1-report.md#5-проверки-и-демонстрация)

На демонстрации с аккаунта А включите `/quiz`, поставьте `/settings 0.7` и отправьте тему. С аккаунта Б оставьте `/study` и `0.3`, задайте другой вопрос. Перезапустите бота, проверьте `/settings` в обоих чатах и продолжите каждый диалог. Затем отправьте `/reset` с аккаунта А и проверьте, что аккаунт Б по-прежнему может продолжить разговор. Сбой API и разбиение длинного ответа воспроизводятся в автоматических тестах. [Инструкция запуска](../README.md) · [Тесты сценариев](../tests/test_lab1.py)
