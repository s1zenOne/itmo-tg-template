# Инструкции для работы с репозиторием

## Источники и окружение

- Корень проекта — `itmo-tg-template`. Работай из него. Перед правками прочитай `README.md`, нужный раздел `docs/labs-guide.md` и проверь `git status`.
- Проект использует Python 3.12, aiogram 3 и PostgreSQL через пул asyncpg. Точка входа — `app/__main__.py`, настройки — `app/config.py`, маскирование секретов — `app/logging_setup.py`. Сохраняй локальный запуск, healthcheck и корректное завершение.
- Для лабораторной № 1 используй [раздел методички](docs/labs-guide.md#lab1), [промпт реализации](docs/lab1-prompt.md) и [шаблон отчёта](docs/labs-guide.md#appendix-report). Общие правила работы с ИИ и данными описаны [в методичке](docs/labs-guide.md#ai-use).
- Для подготовки локального окружения используй `bash scripts/start.sh --setup-only` на macOS/Linux или команду из README для Windows. Не запускай второй polling-процесс с тем же токеном.

## Git

- Фиксируй **каждое завершённое изменение отдельным Git-коммитом**. Один коммит должен содержать одну логическую правку, её тесты и необходимую документацию. Выполни связанные проверки, просмотри staged diff и сделай коммит сразу после завершения правки.
- Добавляй в коммит только свои файлы или свои фрагменты. Сохраняй изменения пользователя. В сообщении коммита кратко укажи результат.
- Тег `lab1` ставь на коммит, который содержит проверенную сдаваемую версию. Существующие теги не переназначай. Публикуй коммиты и теги по запросу пользователя.

## Требования лабораторной № 1

- Бот отвечает на текст в личных чатах. `/start` описывает команды. Режимы — `/study` по умолчанию, `/translate` и собственная команда с отдельной задачей. В промпте реализации выбран `/quiz`. У каждого режима отдельная системная инструкция, минимум одна с few-shot-примерами.
- В PostgreSQL храни раздельные историю, режим и температуру пользователей с восстановлением после перезапуска. Смена режима очищает историю. `/reset` очищает только историю вызывающего. `/settings` показывает режим, модель и температуру, принимает `0.0`, `0.3`, `0.7` или `1.0`. Изменение действует со следующего запроса. Команды не передаются модели.
- Ограничивай контекст по числу сообщений и оценочному объёму, сохраняй роли, порядок, инструкцию и текущий запрос. Пользовательские значения передавай в SQL параметрами. Ошибка модели не создаёт реплику ассистента в истории.
- Показывай состояние обработки. Обрабатывай таймаут, сбой API и пустой ответ. Длинные ответы дели на части до 4096 символов без потери текста. Для API задавай адрес, ключ и имя модели отдельными переменными окружения. Описывай параметры в `.env.example`. В логах фиксируй модель, длительность, результат и безопасный ID запроса. Ключи, токены, системные инструкции и переписку не логируй. Секреты храни локально и не добавляй в Git, отчёт или промпты.
- Codex CLI или OpenCode CLI можно использовать для ответов бота, если подтверждены отдельная системная инструкция, роли истории, независимость запросов, изоляция инструментов и передача четырёх значений `temperature` провайдеру. Для OpenCode V2 проверяй параметры варианта модели на выходе к провайдеру. Если условия не выполняются, используй согласованный OpenAI-совместимый API или локальную модель.

## Проверки и сдача

- Покрой восемь обязательных сценариев из методички тестами с подменой Telegram и LLM. Из `.venv` запускай `python -m pytest -q`, `python -m ruff check .`, `python -m ruff format --check .` и `python -m pip check`. На macOS/Linux Docker-тесты можно запустить через `RUN_INTEGRATION=1 python -m pytest -m integration -v`.
- Для эксперимента собери 12 реальных ответов с `/reset` перед каждым запросом. Используй по три прогона на каждую температуру при одинаковых остальных настройках. Зафиксируй дату, модель, версию API, запрос, системную инструкцию, длину ответов, формат, наблюдения и токены, если доступны. Отдельно сравни неполную и улучшенную инструкции.
- В отчёт включи фактические результаты, известное ограничение и декларацию использования ИИ с реальным примером исправленного или отклонённого предложения. Подготовь демонстрацию с двумя пользователями до и после перезапуска, сбоем API и длинным ответом. Невыполненные проверки явно помечай.
